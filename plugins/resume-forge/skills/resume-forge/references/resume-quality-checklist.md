# ResumeForge 简历质量检查清单

本文件只用于交付前检查。检查发现问题时回到数据契约或写作指南修正，不在检查阶段推断事实。

## 自动可检项目

### 结构

- [ ] 实际出现的一级模块顺序为：基本信息、教育背景、专业技能、工作经历、项目经历、个人优势。
- [ ] 省略模块后剩余模块相对顺序不变；不存在空标题、“暂无”或空白占位模块。
- [ ] 个人优势如出现则位于末尾；无证据或用户不要时整段不出现。
- [ ] 工作经历和项目经历均按时间倒序。
- [ ] Markdown 标题层级稳定：姓名或文档标题仅用 `#`；模块用 `##`；具体教育、工作和项目条目用 `###`；项目字段子标题不得跳级或伪装为一级模块。
- [ ] 教育、工作和项目标题行均有三个字段位置；工作经历含“工作内容”子标题。
- [ ] 每个项目内部严格保持“项目背景 → 技术栈 → 工作内容”。

### 事实与状态

- [ ] 正文中的每条声明都能映射到数据记录，且状态均为 `verified`。
- [ ] `needs-confirmation` 只出现在正文之外的问题清单；`confirmed-absent` 与 `omit` 未进入正文。
- [ ] 没有把模板或指南示例当作候选人事实，也没有无来源的公司、项目、技术、职责或指标。
- [ ] 精确量化记录含基线、结果、单位、周期、测试或统计环境、来源和本人贡献边界。

### 术语、语言与重复

- [ ] 技术术语、大小写、版本、日期格式、角色名称和时态前后一致。
- [ ] 无错别字、病句、歧义、口号、过度修饰和不必要的第一人称。
- [ ] 每条只表达一个主题；技能概括与经历证据互相印证但不逐字重复。
- [ ] 加粗克制，没有整段加粗或把未经确认的词作为重点。

### 篇幅与 JD

- [ ] 相关且证据充分的信息优先，重复和低价值流水账已压缩。
- [ ] 没有为强行一页而使用不可读字号、删除高价值事实或改变固定模块顺序。
- [ ] 有 JD 时存在“JD 要求 → 已有证据”映射，正文关键词都能回溯到已有事实。
- [ ] 无 JD 时明确为通用版本，且未猜测岗位要求。

### 隐私、链接与占位内容

- [ ] 正文不含密钥、身份证件、未经许可的内部地址、敏感业务数据或不应公开的个人字段。
- [ ] 链接格式合法，无控制字符或危险协议；显示文字简洁且未暴露本地绝对路径。
- [ ] 未遗留“待补充”“稍后填写”“示例内容”、连续下划线、空括号、空链接或其他占位表达。
- [ ] 首版交付物明确是 Markdown，未宣称已生成 HTML、PDF 或已处理照片。

## 命中后必须由用户确认

自动扫描下列高风险词或模式只能触发复核，不能自动证明其真实：

- 角色边界：`主导`、`独立`、`负责`、`参与`、`从 0 到 1`。
- 熟练度：`了解`、`熟悉`、`掌握`、`精通`。
- 发布与归属：`上线`、`开源`、`原创`、`个人项目`、`团队项目`、`教程项目`。
- 结果与量化：`提升`、`降低`、`节省`、`优化`、百分比、倍数、金额、耗时、规模数字、`QPS`、`用户量`、`交易量`。
- 能力与实现：AI 技能、AI 项目、`AI 生成占比`、本人实现、本人测试以及可独立完成的能力承诺。

对每次命中，必须由用户确认以下事实后才能保留：

- [ ] 项目、单位、作品、链接与候选人的真实归属。
- [ ] “参与、负责、主导、独立”等职责范围，以及团队成果与个人贡献边界。
- [ ] “了解、熟悉、掌握、精通”等熟练度与实践证据。
- [ ] 精确数字的完整口径、来源和本人贡献，不存在把 `20%` 写成 `90%` 的放大。
- [ ] 上线、开源、公开地址和材料披露状态真实、有效且允许公开。
- [ ] 教程、开源或团队项目已如实披露来源与个人增量，没有换名隐藏来源。
- [ ] AI 相关内容确由本人实际实现、测试并理解，而不是为匹配 JD 临时补入。
- [ ] 个人优势每条都有具体经历证据和实际价值，不是由空泛自评扩写。
- [ ] 联系方式、照片、个人字段、内部材料和公开链接的披露范围符合用户意愿。

## 交付门禁

只有自动可检项目全部通过、高风险命中全部获得用户明确确认，且正文外不存在会改变成稿的未解决冲突时，才可标记为可交付 Markdown 成稿；否则只交付基于 `verified` 内容的审阅稿，并在正文外列出合并后的确认问题。
