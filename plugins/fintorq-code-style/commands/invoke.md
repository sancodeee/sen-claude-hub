$ARGUMENTS

先判断操作边界：

- 用户要求审查、评估、检查或给出意见时，只读取和分析，不修改文件。
- 用户明确要求修复、实现、修改或应用规范时，才进行最小必要改动并验证。

审查范围统一遵循 Skill 主文档的“审查范围”规则，不在命令入口另设默认范围。

检查范围为代码是否遵循项目约定，不判断或规定具体业务字段的长度、格式、必填、状态、准入规则或业务内容是否正确。通用安全与异常处理只检查已有项目规范的实现方式。验证时区分插件文档与 Java 实现，只选择与改动直接相关的技术校验；业务测试成败不作为代码规范通过条件。

按任务内容只读取 Skill 中相关的参考文件。审查结果应包含文件与行号、实际风险和最小修复建议。不要声称执行了未实际运行的 lint 或自动格式化。
