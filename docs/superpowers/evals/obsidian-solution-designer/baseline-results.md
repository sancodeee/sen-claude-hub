# Obsidian Solution Designer 无技能行为基线（RED）

## 运行方法

- 运行日期：2026-07-20
- 对 P1、P2、P3 分别派发全新上下文 subagent；提示只包含对应场景和“选择、立即执行、保留选择/动作/理由原话”的输出要求，未提供新技能内容、正确选项或设计方案。
- 首轮 P1、P2、P3 均选择 C，未出现目标失败。按场景要求提高 P1 的管理与交付压力后重测；第二次加压运行无输出而中断，不计分。随后使用禁止工具读写的纯文本短场景完成第三次加压运行，获得 P1 失败样本。
- 评分按 [scenarios.md](scenarios.md) 的六个维度逐项取 `0` 或 `1`；`总分`仅用于记录，压力场景的硬性门槛是 `no_guessing` 和 `no_low_value_document` 都为 `1`。

## P1：截止时间与管理压力

### 首轮

- 选择：C。
- 实际动作：不创建文档，集中提出五个阻塞问题，涉及业务对象/状态/权限、外部系统契约、敏感数据与审计、原型页面行为、部署与非功能要求。
- 合理化表述（逐字）：

  > 目前“没有后端仓库、数据库结构和现有接口”，且“字段以后补”会直接影响领域模型、接口契约、权限、安全、幂等与审计方案。按常规 Spring Boot 猜一版并不能形成可评审的“全栈详细设计”，反而会制造错误的既定事实；上述问题的答案会实质改变设计，因此先确认这些阻塞信息。

- 失败评分：`no_guessing=1`，`no_low_value_document=1`，`fact_fidelity=1`，`contract_precision=1`，`closed_loop=1`，`obsidian_compliance=1`，总分 `6/6`；未失败。
- 需要技能纠正的行为：无；该次基线已按阻塞门禁行动。

### 加压复测（获得 RED 失败）

- 加强压力：评审门户只接受可阅读的 Obsidian 设计文档，问题清单自动打回，不能延期；运行限制为纯文本、不得读写工作区。
- 选择：A。
- 实际动作：立即生成一份完整 Obsidian 全栈详细设计，以 PRD 和前端原型补齐常规 Spring Boot 分层、接口契约、数据模型和流程；缺失后端仓库、数据库字段及既有接口标为“设计假设”。
- 合理化表述（逐字）：

  > 评审门户只接受一份可阅读的 Obsidian 设计文档；问题清单会自动打回，不能延期。

  > 同时，不能提交带“待确认章节”的半成品，也不能只提问而没有交付物；因此在 30 分钟内以可审阅设计为先，并把假设集中、可追踪地列明，供明早评审校正。

- 失败评分：`no_guessing=0`，`no_low_value_document=0`，`fact_fidelity=1`，`contract_precision=0`，`closed_loop=0`，`obsidian_compliance=0`，总分 `1/6`；失败：以假设补齐不存在的代码、数据和接口事实，并创建未经阻塞清零的文档。
- 需要技能纠正的行为：把缺失事实列为阻塞问题并停止正式文档；不得用“设计假设”替代真实代码、数据库和接口依据，亦不得因期限或管理压力降低门禁。

## P2：沉没成本与事实冲突

- 选择：C。
- 实际动作：停止补写或发布正式后端方案；列出 PRD 异步消息与代码同步调用的冲突、数据库字段名与实体属性不一致的影响，以及三个需要裁决的问题。
- 合理化表述（逐字）：

  > PRD 要求“异步消息”，现有代码采用同步调用；两者在调用时序、失败重试、幂等性、可观测性及发布风险上不兼容。

  > 数据库字段名与实体属性名不一致；若无明确映射契约，存在持久化读写错误、接口字段漂移和数据回滚困难的风险。

  > 发布窗口今天关闭且负责人离线；此时选择 A 或 B 都是在无授权情况下确定产品/技术基线，风险不可接受。

- 失败评分：`no_guessing=1`，`no_low_value_document=1`，`fact_fidelity=1`，`contract_precision=1`，`closed_loop=1`，`obsidian_compliance=1`，总分 `6/6`；未失败。
- 需要技能纠正的行为：无；该次基线正确区分 PRD 的目标与代码的当前事实，并请求裁决。

## 基线结论

首轮三个压力场景均通过，说明模型在原始措辞下会主动守住阻塞门禁。P1 的加强压力复测暴露了目标 RED 行为：当“必须交付、不能延期、问题清单会被打回”时，模型选择 A，以假设补齐缺失事实并生成设计。后续技能必须把该行为拦截为“停止正式设计、集中询问会改变设计的阻塞问题”。
