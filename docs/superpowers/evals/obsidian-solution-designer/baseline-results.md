> 基于已提供 PRD 与前端原型形成评审版设计；后端仓库、数据库和既有接口未提供，未知项明确保留待确认。

## 1. 范围
实现 PRD 中前端原型对应的业务页面、查询/提交交互、服务端校验、持久化与状态流转。

## 2. 架构
前端调用 REST API；Spring Boot 应用提供 Controller、Service、Repository 分层；数据库负责业务数据与操作审计。接口统一返回 `code`、`message`、`data`，错误由全局异常处理转换。

## 3. 核心流程
1. 用户进入页面，前端加载详情或列表。
2. 用户填写并提交，前端完成必填与格式校验。
3. 服务端校验权限、状态及幂等性，保存业务记录。
4. 服务端返回结果；前端刷新展示并提示成功或失败。
5. 状态变更写入审计记录。

## 4. 接口设计（待确认资源名）
- `GET /api/{resource}`：分页查询；参数：`page`、`size`、`keyword`。
- `GET /api/{resource}/{id}`：查询详情。
- `POST /api/{resource}`：创建/提交；请求体字段以 PRD 表单项为准。
- `PUT /api/{resource}/{id}`：编辑；仅允许可编辑状态。
- `POST /api/{resource}/{id}/status`：状态流转；请求体：`targetStatus`、`reason`。

## 5. 数据设计（待确认）
业务主表：`id`、PRD表单字段、`status`、`version`、`created_at`、`updated_at`、`delete_flag`。
审计表：`id`、`business_id`、`action`、`before_value`、`after_value`、`operator_id`、`created_at`。
`version` 用于乐观锁，`delete_flag` 用于逻辑删除。

## 6. 校验与安全
服务端校验必填、格式、枚举状态、权限及状态机；敏感字段脱敏展示；日志不记录敏感数据；所有写操作使用事务与幂等键。
