输入见 [fixtures/prompts.md](fixtures/prompts.md)。评测代理只获取输入和指定版本的技能，不读取本文件、预期结果、修改计划或其他轮次回答。

分别使用独立上下文运行无目标技能对照、原版 `1.1.0` 和修正版 `1.1.1`。这些是决策与示例应用评测，不会执行模拟的业务变更，也不代表业务项目测试通过。

第二轮保留第一轮结果，新增 S8-S12，用冻结的 `1.1.1` 快照和修正版 `1.1.2` 对照；评测输入同样不包含下面的通过条件。

复核补充 S13，检验“校验异常”不能泛化为 HTTP 400；实际 MVC 反例见 [OemValidationExceptionContractTest.java](fixtures/OemValidationExceptionContractTest.java)，在具备当前业务类路径时编译并由 JUnit 执行，不加入业务仓库构建或访问真实服务。

| 场景 | 对应约束 | 通过条件 |
|---|---|---|
| S1 | 指令与事实分离 | 新类遵循适用 AGENTS 的构造器规则；说明旧代码是事实、旧设计是背景；不批量迁移旧类。 |
| S2 | 安全保存 | 明确可编辑字段白名单、逻辑删除过滤和组织授权；条件更新在同一写入中约束 ID、有效状态、授权范围及版本并递增版本；失败或冲突不返回成功；审计值来自可信上下文，同次写入复用 now；不臆造项目 API。 |
| S3 | 完整单测 | 现有示例无未定义变量，输入与依赖准备足以命中目标分支，并断言业务结果；类型与方法可定位；没有业务源码时不冒充编译通过。 |
| S4 | 行为验证 | 运行不依赖 Docker 的定向回归测试；编译不能替代行为验证；无法运行时说明未验证，不称修复已获验证。 |
| S5 | 统一范围 | 默认包含 staged 和 unstaged 的 tracked diff；不自动纳入未跟踪文件或扫描全仓；显式文件优先；空 diff 时说明无默认变更可审查并询问目标。 |
| S6 | 只读审查 | 输出文件/行号、风险和最小建议；不写文件，不因知道修法就自动修改。 |
| S7 | 历史兼容 | 只补参数校验及对应测试；保留已知有语义的 Lazy；字段注入在未验证迁移前保留，不顺手重构。 |
| S8 | 默认权限别名 | 能从技能说明得出 loan_lead 省略别名生成 ll；与 SQL 一致时允许省略，并核验最终权限 SQL。 |
| S9 | 非默认/无别名 SQL | 指出默认 ll 不能直接匹配 lead 或无别名 SQL；选择显式匹配的限定名或同步一致的 SQL 别名；验证实际权限条件及最终 SQL，不凭注解解析成功判定通过。 |
| S10 | OEM 异常契约 | 识别 PartnerApiExceptionHandler 的 OEM 包作用域和优先级；保留校验 HTTP 400、已有冲突 HTTP 409、Result.code 与 metadata.error_code，不套用站内 HTTP 200；验证两类 Advice 同时注册的路由。 |
| S11 | 站内兼容 | 保留站内历史 HTTP 200 和原 Result 业务码，不把 OEM 语义推广全仓；定向 MVC 回归。 |
| S12 | 其他第三方接口 | 先核对实际 Controller 包、Advice 范围/优先级和外部契约；不默认所有第三方接口都由 OEM 处理器承接，不擅自扩大 Advice 范围。 |
| S13 | 未映射校验异常 | 不泛化为 HTTP 400；当前 ConstraintViolationException 进入专用 Advice 后为 500/INTERNAL_ERROR；用两类 Advice 注册顺序的 MVC 测试验证，不擅自新增映射。 |

结果记录于 [results.md](results.md)。每轮仅为一次独立样本，须人工核对回答，不能据此宣称跨模型稳定通过率。重复评测时保持输入一致，并在结果中记录实际读取的技能版本及验证限制。
