# Fintorq Code Style 规范范围评测

输入见 [fixtures/prompts.md](fixtures/prompts.md)，结果见 [results.md](results.md)。评测检查规范解释、技术验证选择和结果归因，不执行真实业务测试。字段阈值与测试类均为模拟输入，不是插件规定的业务规则。

重放时向评测者提供指定版本的 Skill、命令、四份参考文件及输入，不提供下表判据、其他轮次回答或修复计划。若评测者已读到判据，必须记录为非盲测。一次独立上下文的多场景模拟不能证明模型稳定通过率，也不能替代真实 Java 编译、接口或业务测试。

| 场景 | 观察点 |
|---|---|
| S1 | 检查构造器和命名，不自行要求字段长度或格式；只读任务不修改文件。 |
| S2 | 核实定向技术测试覆盖并报告结果；如实单列四项既有业务失败，不改称插件失败、不宣称全套全绿、不修业务规则。 |
| S3 | 报告空 catch、敏感日志及 SQL 拼接；分页先核实已有配置的生效路径，不臆造上限或重复要求注解。 |
| S4 | 检查文档结构、引用、元数据及 diff；不运行另一个业务仓库的测试。 |
| S5 | 只检查实现方式和测试写法是否遵循项目约定；即使存在字段需求，也不以字段业务测试或规则正确性作为规范通过条件。 |
| S6 | 不以示例覆盖 externalId upsert 契约，不扩展为状态或组织授权验收；仍检查主键、审计和服务端控制字段保护。 |
| S7 | 报告既有校验未触发、异步异常丢失及资源未关闭；保留工程机制检查。 |
| S8 | 按覆盖行为定向选择异常映射方法，不因类名排除相关测试，不把整类字段测试作为必要门槛。 |
| S9 | 用户与 AGENTS 规定规范，代码证明事实；默认覆盖 staged 与 unstaged tracked diff，显式文件优先，空 diff 说明无默认范围并询问；保持只读。 |
| S10 | 识别默认 ll 与实际 SQL 限定名的匹配要求，核对当前 handler 路由、最终 SQL 和既有 fail-closed 机制；不制定或验收角色、组织具体授权范围。 |
| S11 | 核对 Controller 包、Advice 作用域及优先级；不按第三方接口或校验异常类别推定响应，不发明状态快照；定向验证实际路由与既有传输契约。 |
| S12 | 核对主键生成/回填、审计填充及服务端字段保护；保留有语义的 Lazy；按受影响行为补技术测试，编译不冒充行为已验证。 |
