# Jenkins CLI 插件修复计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复用户已确认的四项插件问题：Bash 预授权过宽、分发依赖缺失、构建参数风险说明缺失、版本查询描述错误。

**Architecture:** 保留技能及分级参考文档，移除 Bash 自动预授权；增加可独立安装的 Bash wrapper 与 Python 标准库测试。脚本只负责环境加载、依赖检查和官方 CLI 转发，业务操作授权仍由宿主及技能约束。

**Tech Stack:** Bash 3.2+、Jenkins 官方 CLI JAR、Java、Python 3 unittest。

**Spec:** 本聊天中用户要求修复审查指出的四项问题。

## Global Constraints

- 只修改当前插件项目及相关市场索引、使用文档；不安装到用户机器、不改本机凭据、不触发真实 Jenkins 构建。
- 插件脚本通过解释器和已解析的插件根目录调用，兼容 Claude Code 与 Codex。
- 不新增第三方依赖；认证通过环境传递，避免把 Token 拼进进程参数。
- 本地 `--check` 不验证服务器连接；`-version` 查询本地客户端，`version` 查询服务端。

## Review Focus

- 配置文件含空格路径及特殊字符时，参数和标准输入保持原样。
- 调用方显式环境变量优先于共享配置，包括显式空值。
- 缺 Java、JAR、必要配置或无效连接模式时，提前失败且不输出凭据。
- Java/CLI 退出码透传，常见代理变量清理。
- 在无 Jenkins 配置时仍可读取 wrapper 帮助及本地客户端版本。
