# Git Worktree Helper 优化计划

> **For agentic workers:** 使用 superpowers:executing-plans 按任务执行；修改脚本先验证失败测试，再实现并验证通过。

**Goal:** 修复评审发现的数据保留和错误处理缺口，使 skill 的操作规则与脚本一致。

**Architecture:** 保留现有 Python 标准库脚本、三方比较和插件目录结构。脚本负责确定性校验，skill 集中维护决策和授权边界，commands 仅分发操作。

**Tech Stack:** Python 3、Git、unittest、Markdown。

**Spec:** 本计划的“变更约定”，落实本次对话中已经评审并获准优化的事项。

## 变更约定

- 保留目录 basename 等于分支名最后一级的现有规则，不增加移动或重命名功能。
- 文件基线升级为 v2，记录普通文件权限；兼容 v1 的内容比较，无法推断的权限差异保守阻断。
- 配置回收比较内容、类型和普通文件权限；两侧冲突时不覆盖。
- 默认检查非受管忽略文件，按 dirty_worktree 阻断；受管忽略配置仍可回收。显式 --force 可以丢弃非受管文件，但不能绕过配置冲突、主 worktree 或主 HEAD 分支保护。
- 非法 JSON 结构和条目返回 config_sync_error，保留 worktree。
- 创建后配置复制或基线写入失败，返回 create_incomplete，保留目录和分支，并给出状态检查指引。
- 授权明确且覆盖已报告风险时不重复询问；信息不全时只询问影响操作的缺失参数。
- 缩减重复命令说明；不为移动请求自动扩展插件。

## Global Constraints

- 不引入依赖或框架；不修改其他插件及用户原有未跟踪目录。
- 仅变更当前工作目录中的文件，不自动提交、合并或发布。
- 两套 plugin.json、Claude 市场清单和 README 当前统一为 2.1.4（前两轮分别为 2.1.2、2.1.3）。
- 不修改已安装的插件缓存；测试只在临时仓库产生 Git 状态。

## Review Focus

- v1 基线在内容未变或仅单侧修改时仍可正常清理；权限信息不足时不猜测。
- --dry-run 不同步、不删除，--force 也不能突破硬性保护。
- 忽略目录内的非受管文件仍须阻断；受管配置被忽略不影响回收。
- 创建失败后，已有 worktree/分支保留，不能输出成功或建议覆盖重建。
- 模型对已授权丢弃、不可绕过冲突、纯咨询和不支持操作采取对应动作。

## 第二轮修复约定

- 配置计划保留用于比较的原始快照；同步前、同步后和真正删除前验证状态。检测到变化时以 config_sync_changed 阻断，--force 不能绕过。
- 同时复核 worktree/主项目的 HEAD、分支与非受管脏路径集合，检测期间新提交、切换分支或新文件时以 worktree_changed 阻断。此复核不充当文件系统锁，清理期间必须暂停其他写入。
- 顶层普通或失效符号链接按原始链接文本复制，不展开目录，不覆盖目标已有的失效链接。相对链接在目标目录中仍按相对路径解释。
- 基准引用先解析并固定为 commit，默认基准通过 HEAD 解析以避免同名标签歧义；dry-run 基于该提交的配置文件树及适用的 sparse checkout 规则判断跳过/复制，实际创建也使用同一 commit。
- 继续保留目标配置整项跳过、无业务代码复制、旧基线兼容、默认预检和授权边界。

## 第三轮修复约定（373d94d 之后）

- 有已暂存的受管配置且索引对象、类型或执行权限与工作区不同时，以 config_index_conflict 阻断并保留索引、工作区和分支；--force 不能绕过。直接比较对象以覆盖 assume-unchanged / skip-worktree；正常暂存配置继续回收。
- 清理状态记录受管索引条目；期间索引变化也需要重新预检。
- 主 worktree 结合实际工作树身份、Git 注册列表与创建时保存的已验证主目录定位，不依赖元数据目录名字；使用 NUL 分隔解析。无法定位的旧独立元数据布局停止并提示 --repo 真实主目录；无主工作树的 bare 仓库不能作为配置回收目的地。
- 显式基准名先匹配 refs/heads，再匹配 refs/remotes，最后按 Git 提交表达式解析；完整 refs/tags/... 保留显式标签选择。默认 HEAD 行为保持不变。
- 版本同步到 2.1.4。只提交本轮修复、测试及对应说明，不推送；不修改用户原有未跟踪目录。
