# Fintorq Code Style 规范范围修正

本计划按用户最新要求取代此前包含业务保存、状态和字段验收的计划。旧版本记录保留在 Git 历史，不作为当前插件规范或本版验证证据。

目标是使 AI 编写、审查和修改 Fintorq Java 代码时遵循项目代码规范。实际删除业务规则、业务内容和具体授权范围的检查、示例及验收要求；业务测试成败不作为代码规范通过条件。

## 范围与整合

- 只修改本仓库目标插件、相关说明、发布元数据及评测资料；不修改或测试外部 Fintorq 业务仓库，不更新本机安装缓存。
- 以已核实的远端 main `053ed34f58a3eb6684d9132512f1cee6e9e164aa` 为基线，在隔离分支 `fix/fintorq-code-style-scope` 整合原工作树改动。
- 已发布版本为 `1.1.2`，本版升级为 `1.1.3`；同步两个 plugin.json、Claude marketplace 和 README，保持两个市场的路径一致。
- 保留指令与事实分离、只读审查、staged/unstaged 默认范围、显式范围优先、特殊构造器兼容、别名技术接入、实际 Advice 路由及 Docker/Testcontainers 边界。

## 工作项

- 删除状态策略业务单测、统一业务保存决策、具体组织/角色授权与状态验收、业务测试通过门槛、静态业务响应快照和业务一致性策略要求。
- 保留命名分层、构造器注入、SLF4J、SQL 安全、服务端字段保护、主键与审计用法、既有校验触发、异常传递、资源释放及框架接入技术验证。
- 更新场景输入、判据与实际结果，区分独立模拟、静态检查和真实命令；不沿用旧轮次的 Java 或业务测试通过结论。
- 执行适用的完整插件结构和元数据检查、引用与围栏检查、差异检查及独立整体复核。
- 确认没有问题后提交，并以普通非强制推送发布修复分支；读取远端分支 SHA 确认提交存在。不推 main、不合并、不部署、不创建 PR。

实际结果与限制见 [评测记录](../evals/fintorq-code-style/results.md)。
